# 遊戲在線狀態與指令場次

## 已實作

- Unity 啟動時產生新的 `sessionId`，並用 HTTP PUT 每 5 秒更新 `rooms/ab123/gameStatus`。
- 只有伺服器確認寫入成功後才接受指令；寫入失敗時停用接收並更換場次，下一次回報會重試。
- Unity 心跳使用即時等待，不受遊戲 `Time.timeScale` 影響；不再等待桌面 SDK 的 `.info/connected` 或 `OnDisconnect`。
- 狀態包含 `sessionId` 與 Firebase 伺服器時間 `lastSeen`。
- Unity 正常結束時嘗試刪除狀態；強制終止時靠心跳過期停用手機按鈕。
- 手機必須與 Firebase 連線、取得場次編號且心跳在 15 秒內，才允許發送。
- 新指令附上當前 `sessionId` 與 Firebase 伺服器時間 `time`。
- Unity 收到指令及執行佇列時都檢查場次；沒有場次或場次不符的舊指令直接移除，不執行效果。
- 既有病毒與胃液遮擋功能、各自冷卻繼續使用；冷卻結束不會誤啟用離線按鈕。
- 原本「10 分鐘閒置」實際寫成 10 秒，已修正為 10 分鐘，避免等待遊戲啟動時過早退出。

## 測試與部署

Unity 腳本已用現有 Unity／Firebase 參照編譯；網頁以模擬 Firebase 測試離線、重啟、
場次更換、心跳逾時、冷卻、發送前切換場次與權限錯誤。
尚未執行 Unity Play Mode、手機實機測試或部署網站。

Firebase 規則需允許目前無登入驗證的 Unity REST 寫入房間 `gameStatus`、手機讀取該狀態。
未自行修改資料庫規則。此設計預期每個房間只有一個 Unity 主遊戲。
斷線偵測不是即時保證；強制終止可能需等伺服器判定斷線或心跳過期。

## 實機驗證步驟

1. 更新線上網站或使用本機測試網址；Unity 等待重新編譯。
2. Unity 未執行：兩個可用按鈕應停用，顯示等待遊戲啟動。
3. Unity 進入 Play：在線狀態更新後按鈕可用，病毒與胃液遮擋都可觸發。
4. Unity 停止 Play：按鈕應停用；再次啟動不補播上一場指令。
5. Unity 強制關閉或斷網：等候最多約 15 秒檢查手機停用。
6. 用資料庫或舊版網頁留下無 `sessionId` 的指令：Unity 應略過並刪除。
